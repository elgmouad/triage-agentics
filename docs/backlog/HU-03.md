## Historia de usuario

**Como** agente de soporte, **quiero** que cada ticket nuevo llegue ya clasificado con categoría, prioridad, resumen y un borrador de respuesta, **para** dedicar mi tiempo a resolver y no a clasificar.

## Contexto

- **Caso de uso:** CU-03
- **Reglas de negocio:** RN-04, RN-07
- **Servicio:** `servicio-agente-triaje`
- **Interfaces:** evento `ticket.creado`, `GET /internal/tickets/{id}`, `GET /internal/clientes/{clienteId}/historial` (herramienta), `PUT /internal/tickets/{id}/triaje`

## Criterios de aceptación

- [ ] **Dado** un evento `ticket.creado`, **cuando** el agente lo consume, **entonces** el ticket pasa a `TRIE` con categoría, prioridad, resumen, confianza y borrador.
- [ ] **Cuando** el modelo lo necesita, **entonces** invoca la herramienta `obtenerHistorialCliente` y tiene en cuenta su resultado.
- [ ] **Dada** una respuesta del LLM que no respeta el esquema JSON, **cuando** se valida, **entonces** se trata como un fallo del proveedor.
- [ ] **Dada** una confianza inferior a 0,7, **cuando** se guarda el triaje, **entonces** el ticket se marca `revisionManual = true`.
- [ ] Cada llamada al LLM se registra en `llamada_llm` (proveedor, modelo, tokens, latencia, éxito).
- [ ] El evento solo se confirma (`XACK`) después de guardar el resultado.
