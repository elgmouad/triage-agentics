## Historia de usuario

**Como** supervisor, **quiero** que el triaje siga funcionando aunque un proveedor de IA falle o se quede sin cuota, **para** que ningún ticket quede sin clasificar.

## Contexto

- **Caso de uso:** CU-03
- **Reglas de negocio:** RN-06
- **Servicio:** `servicio-agente-triaje` (`LlmRouter` + Resilience4j)
- **Endpoint:** `GET /api/v1/triaje/proveedores`

## Criterios de aceptación

- [ ] **Dado** Ollama detenido o con *timeout*, **cuando** llega un ticket, **entonces** se usa Anthropic y el ticket queda triado.
- [ ] **Dados** varios fallos seguidos, **cuando** se supera el umbral, **entonces** el circuit breaker del proveedor pasa a `OPEN` y las peticiones van directamente al proveedor secundario; tras la espera pasa a `HALF_OPEN`.
- [ ] **Dado** un error `401`/`403` de Anthropic, **entonces** el circuito se abre sin reintentos; los errores `429`/`5xx` se tratan como temporales.
- [ ] **Dado** que ambos proveedores fallan, **cuando** se procesa el ticket, **entonces** se clasifica por reglas de palabras clave y pasa a `EN_ATTENTE_DE_TRI`.
- [ ] El orden de proveedores y los *timeouts* se leen del Config Server y se cambian sin recompilar.
- [ ] `GET /api/v1/triaje/proveedores` muestra el estado de cada circuito.
- [ ] La clave de Anthropic se lee de una variable de entorno y nunca aparece en el repositorio.
