## Historia de usuario

**Como** supervisor, **quiero** que los tickets en riesgo de incumplir su SLA se escalen automáticamente, **para** intervenir antes de incumplir el compromiso con el cliente.

## Contexto

- **Caso de uso:** CU-06
- **Reglas de negocio:** RN-02, RN-03
- **Servicio:** `servicio-tickets` (tarea planificada)

## Criterios de aceptación

- [ ] **Dado** un ticket que alcanza el 80 % de su plazo de primera respuesta sin respuesta, **cuando** se ejecuta la tarea, **entonces** se marca `escalado = true`.
- [ ] **Cuando** consulto `GET /api/v1/tickets?escalado=true`, **entonces** veo los tickets escalados.
- [ ] Un ticket no se escala dos veces.
- [ ] Los plazos por prioridad y la frecuencia de la tarea se leen del Config Server.
- [ ] Con varias réplicas del servicio, la tarea se ejecuta una sola vez por ciclo.

## Tareas técnicas

- [ ] Tarea `@Scheduled` de verificación de SLA
- [ ] Cálculo del porcentaje de plazo consumido
- [ ] Bloqueo distribuido (p. ej. en Redis) para evitar ejecuciones duplicadas
- [ ] Tests con un reloj simulado (`Clock`)

## Definición de hecho

- [ ] Todos los criterios de aceptación se cumplen
- [ ] Código integrado en `main` mediante Pull Request
