## Historia de usuario

**Como** desarrollador, **quiero** un repositorio con `.gitignore`, estrategia de ramas, commits semánticos y plantillas, **para** trabajar con un flujo profesional y trazable durante todo el curso.

## Contexto

- **Entregable:** Hito 1 — Repositorio de GitHub configurado y entorno de gestión

## Criterios de aceptación

- [ ] El `.gitignore` cubre Java, Maven, IDE, Docker y secretos (`.env`).
- [ ] La estrategia de ramas (`main` + `feature/*`, `fix/*`, `docs/*`, `chore/*`) está documentada en el README.
- [ ] La convención de commits semánticos está documentada y se aplica.
- [ ] Existen las plantillas `.github/ISSUE_TEMPLATE/user_story.md` y `.github/PULL_REQUEST_TEMPLATE.md`.
- [ ] El backlog está registrado como issues con la etiqueta `user-story` y organizado en GitHub Projects por milestones.

## Tareas técnicas

- [ ] `.gitignore`, `.gitattributes`, `.env.example`
- [ ] Plantillas de issue y de pull request
- [ ] Etiquetas y milestones
- [ ] Tablero GitHub Projects con vista agrupada por milestone
- [ ] Sección «Gestión del proyecto» del README

## Definición de hecho

- [ ] Todos los criterios de aceptación se cumplen
- [ ] Código integrado en `main` mediante Pull Request
- [ ] La integración continua (CI) pasa en verde
